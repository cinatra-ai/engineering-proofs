# Round 5 of 5: the personal scope

These pictures come from one real agent run in the personal scope. The
application is a production build of the main line, started the way the
repository's own end-to-end workflow starts it. No development server was used.
The account is invented and the data is seeded: the signer is "Ada Example", the
agent is the Blog Draft Writer Agent, and the run's one input is the sentence
"Why every team needs one shared notebook". Every step was taken by pressing a
control the product drew. The address bar was recorded after each press. Each
picture pair is the same reading in the two palettes; the palette was set on the
page and read back from the page root before the picture was taken.

The personal round runs the same agent that the earlier rounds installed for a
project. Nothing was installed, removed or re-targeted for this round. The
agent's access policy still names the project, and the personal Agents tab still
lists the card, because that tab lists every agent the person may invoke
whatever the policy names. The tab lists 30 cards: the 29 agents the platform
imports at first boot, plus this one. The list is reached by pressing the Agents
tab on the personal landing, and the address becomes the personal Agents
address.

The personal round is the one round whose run addresses are bare. The card's own
Run control points at a scoped address, and pressing it lands the reader on the
bare run address instead, which is what the contract asks for. Every later step
held that address: the Schedule step, the Permissions view, the context gate and
the stopped card all stayed on the run's own bare home, and the notification
page points at the same bare address for both runs of this round. The run's
trail reads "Agents" and then the agent's display name with "Personal (owner)"
beside it. No trail in the round shows a raw id.

One reading was taken with a second organization active in the session. The
personal Agents tab then lists only the 29 platform agents and drops this agent's
card, so there was no card to press and no run to read. The personal landing
itself opened in place and its trail stayed clean, so nothing in that reading is
a fault of the checks this round applies. It is recorded because it differs from
the team and the project surfaces, where the card stays listed whichever
organization is active.

The draft itself could not be written. The model account behind this instance
has no credit left, so the run stops at the model call and the card reads "Run
failed". The two steps that need a written draft are marked blocked, not failed.
Everything before the model call was proved: the context gate offered the
person's own saved idea, the choice was accepted, and the run kept the revision
it read.

One defect is recorded. The run started from the stopped card carries no scope
anchor at all, while its parent carries the person's own anchor. The product
shows the same fault twice more: that second run's trail loses the
"Personal (owner)" words, and the personal Executions list does not hold it.
