# Review gate: a second answer to a decided gate — proof round 3

Three cells, shot at the pushed head of the change under review on a development
boot of the product, against a real agent run dispatched through the product's
own screens.

## What the round raced

A real run of the blog draft writer agent, installed through the product's own
marketplace, writes a blog post and parks at the review of that post — an
artifact review gate. Two signed-in browser contexts then answer the same
pending gate in the same millisecond through a shared trigger, one pressing
Approve and the other Reject. One answer decides the gate; the other is a second
answer to a gate that is already decided, and the review surface draws the
Blocked state for it.

Rounds 1 and 2 of this proof raced a step input gate, which is a different gate
kind: the earlier rounds are superseded by this one.

## Structure

The Blocked state is drawn as ONE bordered box: a 1 pixel border, a 10 pixel
radius and 20 by 16 pixel padding, measured on the card itself in both palettes.
Its ancestors up to the page column carry no border of their own and are not
empty — they hold the gate's own heading and the reviewed post — so the card is
not nested inside a second, empty frame. Measured, not asserted: the ancestor
frame chain is recorded for both palettes in dom-readings.jsonl.

## Readings

`dom-readings.jsonl` carries one appended reading per shutter: the press instants
of both contexts and their difference, which context lost, the typed outcome read
from the losing context's own decision response, the card's box, reason attribute
and text, the Refresh control's box, the ancestor frame chain, the theme state,
and the indicator and band boxes. `measurements.json` carries the per-file
measurements and the database read-backs.

The development-only wrench in the topbar is an artefact of the development boot
this round ran on, named here once; it is not part of any cell.
