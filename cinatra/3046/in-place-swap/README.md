## Defects, as measured

- The review target renders as a blank grey loading skeleton in SIX of the twelve run frames — every pending frame on both surfaces and both themes, and both decided frames on the run page — against §III 'A target is never blank' and §II's requirement that the target name what is under review and pin its exact revision. The conversation surface renders the same artifact correctly in the light decided frame, so the target data exists; the run page never draws it, and neither surface draws it while the gate is pending.
- The placeholder is drawn wrong on every surface and both themes: it names a status ('pending approval' / 'Awaiting input'), reports a result ('No messages yet.'), and carries NO spinning indigo arc — where the drawing says the placeholder is 'the card frame, and a spinning icon… It names no status, reports no result'.
- The run page's placeholder frames (both themes) do not show the drawn run surface at all: no left step rail, no run detail column — a single-column agent Setup tab with the progress card in the body. The rail only appears once the gate is pending.
- On the run-page placeholder the card draws controls to press — 'Continue →' (light), an Idea textarea plus 'Continue' (dark) — where the drawing says the placeholder 'draws nothing to press'.
- The already-answered input gate ('Draft Context') stays in the conversation slot with a LIVE primary 'Continue →' through the pending frames AND after the run has completed, on both themes — a control that must not be there, stacking a second card in a slot the drawing gives one card. The run page correctly drops it, so the two surfaces disagree.
- conversation-decided-dark.png does not picture a decided gate: the settled panel is below the frame edge and the target is still a pulsing skeleton, so the dark decided leg is unproven in pixels.
- The decision floor is not visible in either conversation pending frame (light and dark) — the card runs off the bottom edge behind the composer — so the pending reading's Comment / Reject / Approve and rationale field are attested only in the DOM, never shown.
- A development pill or badge is burned into all twelve run frames — 'Compiling …', 'Rendering …', the Next dev indicator disc (twice drawn over the card body), and in conversation-review-card-pending-dark.png a RED '1 Issue' error badge — against the capture rail's 'no development pill in a frame if it can be avoided'.
- The card header stays present-tense 'Review requested' on every settled reading, on both surfaces and both themes, where the drawing's resolved reading records how it was settled.
- The run page's rail names its work step 'Step 1' where §I says the rail 'names the run's ordered steps'.
- The pending run-page frames carry no prompt window beneath the gate, which §I lists as part of the gate's reading in the run detail.
- The light decided target prints a raw ISO timestamp with milliseconds ('updated 2026-08-29T06:18:35.818Z') where the drawing writes a relative reading ('updated 8 min ago').
- setup-secrets-env-managed-light.png is mislabelled — it shows the MODEL step ('Choose your LLM provider'), not the Secrets screen, and carries no measurement of its own.
- The swap is not proved to happen on its own: the capture record discloses that on BOTH themes the open page still showed the placeholder 240 s after the gate row existed and the card appeared only after a page reload. The drawing says 'It happens on its own: the reader neither asks for the card nor presses anything to bring it.'
- The 'one slot, two readings' comparison cannot be read from the pixels: the placeholder frames and their decided counterparts are at different scroll offsets (and in the dark pair at different points of the run), so sameness of slot rests on the DOM anchor alone, not on the pictures.
- The conversation's review card declares host 'run_card' on the chat thread in both states and both themes (from the record's DOM reading), against the anchor contract's own re-ratification note that the review gate reads 'transcript' on chat_thread and 'composition' on run_card — a host mis-declaration reproduced on this head.
- Scope note, not a frame defect: the ratified drawing at this pin defines only the light palette (--paper #f1f1ed ≈ 239) and draws no dark theme, so the six dark frames (luminance 11.7–16.5) have no drawn colour band to be graded against and are graded on structure only. The six light frames measure 237.7–239.8, inside the light band.

**Overall:** The capture proves the database ordering and, through the DOM anchor, that the card arrives in the same slot with no new turn and no tool call — but as pictures graded against the ratified drawing the set fails: the review target is a blank loading skeleton in six of twelve frames, the placeholder is drawn with a status pill and no spinner everywhere, both run-page placeholder frames show no step rail at all, an answered input gate keeps a live Continue in the slot through and past the decision, conversation-decided-dark shows no decided reading whatsoever, the secrets frame is mislabelled, development chrome (including a red '1 Issue' badge) is burned into every frame, and the swap itself needed a page reload on both themes.
